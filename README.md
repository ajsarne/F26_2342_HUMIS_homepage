The HUMIS project taught me how to use industry-standard applications and write HTML5 and CSS3 to design web pages using the WebStorm code editor. I learned how to organize and simplify code, create components, use tags effectively, and apply basic interactions. It was tricky to understand how nested tags work at first, especially with parent-child hierarchy. However, when I applied my practice with designing on Figma, nesting made sense because they share the same principles.

In the future, if I were to build a website like this, I would prioritize coding templates and styles first. Pages with similar layouts can use one consistent template, then update as more elements are needed. Plus, I’d make sure to create components; that way, it would be easier to make changes or updates without browsing or finding the issue on each page. I would also make sure to get the correct hex codes and font styles immediately, so the website’s brand identity remains consistent.

Now that I have a foundational knowledge of frontend coding, I have an idea of how to design efficiently as a UX Designer. So, moving forward, I'd make sure to structure my frames and groups correctly, and name them accordingly, so it is easier to hand off to developers. Most importantly, I learned the importance of feasibility in design. Yes, the design can look nice, but is it feasible to be coded as a product within the timeline or given limitations of an organization?
